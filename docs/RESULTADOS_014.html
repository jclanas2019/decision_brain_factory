Cuatro candidatos y un router local

Se implementaron la red de referencia, un ensemble de tres redes, CORN para Score y una adaptación multisalida de SelectiveNet. El router se guarda, recarga y sirve mediante los mismos contratos, gateway y SDK.

140 pruebas de software aprobadas y 140 en el proyecto generado. Prueba funcional de recarga, decisiones y gate tipado en 300 casos. También se probó registro → servicio → response gate con algoritmos distintos por cabeza.

El ensemble mejora ligeramente la loss de test, pero no supera el criterio de validación para cambiar rutas. El router conserva neural en Choice, Noul y Score. Sus candidatos permanecen incluidos; entrenamientos con otros datos pueden seleccionar otras rutas. No se fuerza diversidad si la validación no la respalda.

Gate de incertidumbre: FAIL. La cobertura conjunta del router es 75,7 %, por debajo del objetivo 90 %. La promoción sigue bloqueada. Los resultados son sintéticos y el harness es conocido. Cero errores observados no demuestra riesgo cero.

Usar el sistema

bash start.sh compare

Prueba, entrena, compara y abre el informe. El código de salida 1 indica que la calidad no pasó, aunque el software y el harness hayan aprobado. Los informes quedan disponibles. Para inferir después:

bash start.sh predict --state examples/example_state.json
